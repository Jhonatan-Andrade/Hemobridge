Hemobridge API

Plataforma de direcionamento de doações de sangue · NestJS + PostgreSQL/PostGIS. Referências (RFxx, RNxx, UCxx) seguem o projeto lógico.

Autenticação

Todas as rotas exigem o cabeçalho Authorization: Bearer <accessToken>, exceto as marcadas como Público. O token é obtido em POST /auth/login e vale por 1 hora (JWT_EXPIRACAO). A cada requisição o usuário é relido do banco: conta desativada, instituição desativada, troca de senha ou logout invalidam o token na hora.

Primeiro acesso (senha provisória)

  1. Contas criadas por terceiros recebem por e-mail uma senha provisória válida por 72h (RN15).
  2. POST /auth/login com a provisória responde "primeiroAcesso": true.
  3. Enquanto isso, só funcionam /auth/me, /auth/logout e /auth/primeiro-acesso*; as demais respondem 403.
  4. POST /auth/primeiro-acesso define a senha e devolve um novo token — o anterior deixa de valer.

Formato de erro

{
  "statusCode": 400,
  "error": "Bad Request",
  "message": ["CPF inválido", "E-mail inválido"]   // texto ou lista
}

Códigos usados: 400 dados inválidos · 401 sem token / sessão inválida · 403 perfil sem permissão, conta ou instituição desativada, primeiro acesso pendente · 404 não encontrado (inclui recurso de outro hospital) · 409 conflito (CPF, e-mail, CNPJ, CRM) · 422 critério de doação não atendido · 423 conta bloqueada por tentativas · 429 limite de requisições (ver cabeçalho Retry-After).

Convenções

  • Campos extras no corpo são recusados (property X should not exist).
  • CPF, CNPJ, CEP e telefone aceitam máscara; são gravados só com dígitos. E-mail é gravado em minúsculas.
  • Senha: 8 a 128 caracteres, com letra maiúscula, letra minúscula e número (RN06).
  • Datas em ISO 8601 (UTC). Datas de nascimento em AAAA-MM-DD.
  • Listas paginadas devolvem { itens, total, pagina, tamanhoPagina }.
  • Na query string, + deve ser enviado como %2B (ex.: tipos=A%2B); a API também aceita A+ sem codificação.
  • Limite geral: 100 requisições/min por IP; rotas sensíveis têm limites próprios.
