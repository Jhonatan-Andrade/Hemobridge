Como iniciar o Hemobridge

Passo a passo para Windows (PowerShell). São três partes: banco e e-mail no Docker, a API e o site.

Primeira vez

Faça os passos em ordem. Se já instalou, vá direto para No dia a dia.

1

Conferir os programas

Abra o Docker Desktop e espere ele terminar de iniciar. Depois, abra a pasta do projeto no Explorador de Arquivos, clique com o botão direito numa área vazia e escolha Abrir no Terminal. Confira:

node -v
npm.cmd -v
docker compose version

Os três precisam mostrar uma versão. O projeto usa o Node 24.

Por que npm.cmd e não npm? O PowerShell do Windows costuma bloquear o npm com "a execução de scripts foi desabilitada neste sistema". Com .cmd no final, funciona sem mudar nenhuma configuração.
2

Criar o arquivo de configuração da API

A partir da pasta do projeto:

cd backend
Copy-Item .env.example .env
notepad .env

Gere o segredo da autenticação e copie o resultado:

node -e "console.log(require('crypto').randomBytes(48).toString('base64'))"

No Bloco de Notas, ajuste estas linhas, deixe as outras como estão e salve:

POSTGRES_PASSWORD=Hemobridge123
DATABASE_URL=postgresql://hemobridge:Hemobridge123@localhost:5434/hemobridge
JWT_SECRET=cole-aqui-o-segredo-gerado
SEED_DADOS_EXEMPLO=true
SEED_SENHA_EXEMPLO=Demo-Senha1

A senha em DATABASE_URL tem que ser igual a POSTGRES_PASSWORD. Estes valores são só para uso local.

Já rodou o projeto em outra pasta deste computador? As cópias usam o mesmo banco no Docker, e ele guarda a senha de quando foi criado. Em vez de criar um .env novo, copie o backend\.env da outra pasta.
FRONTEND_URL aceita um endereço só (http://localhost:5173). Com dois endereços separados por vírgula, os links dos e-mails saem quebrados. Para liberar mais endereços, use CORS_ORIGENS.
3

Subir o banco e a caixa de e-mails

Ainda em backend:

docker compose up -d
docker compose ps
Deu certo se hemobridge-postgres aparece como healthy e hemobridge-mailpit está rodando. O banco pode levar alguns segundos.
4

Instalar a API e preparar o banco

Um comando por vez, em backend:

npm.cmd install
npx.cmd prisma generate
npx.cmd prisma migrate deploy
npx.cmd prisma db seed
Deu certo se as migrations terminam sem erro e o seed mostra Tipos sanguíneos: 8. Com SEED_DADOS_EXEMPLO=true, mostra também Dados de exemplo: 2 hemocentros….
5

Iniciar a API

npm.cmd run start:dev
Deu certo se aparece API rodando na porta 3333 e esta página da API responde com uma lista. Deixe este terminal aberto.
6

Instalar e iniciar o site

Abra outro terminal na pasta do projeto:

cd frontend
Copy-Item .env.example .env
npm.cmd install
npm.cmd run dev
Deu certo se aparece http://localhost:5173. Abra o Hemobridge no navegador e deixe este terminal aberto também.
Se o endereço terminar em 5174, a porta 5173 já está em uso. Feche o outro terminal que está com o site aberto e rode de novo; senão a API recusa o site.

No dia a dia

Com tudo instalado, abra o Docker Desktop e use dois terminais na pasta do projeto.

Terminal 1: banco, e-mail e API

cd backend
docker compose up -d
npm.cmd run start:dev

Terminal 2: site

cd frontend
npm.cmd run dev

Depois de um git pull

Antes de iniciar, atualize em backend:

npm.cmd install
npx.cmd prisma generate
npx.cmd prisma migrate deploy

E em frontend:

npm.cmd install

Para parar

Aperte Ctrl + C nos dois terminais. Para parar também o banco (os dados ficam guardados), em backend:

docker compose stop
Cuidado: docker compose down -v apaga o banco inteiro.

Testar "Esqueci minha senha"

  1. No site, abra Entrar e clique em Esqueci minha senha.
  2. Informe paciente@hemobridge.local e envie.
  3. Abra o Mailpit: os e-mails locais chegam ali, não na sua caixa real.
  4. Clique em Redefinir minha senha. O link vale 30 minutos e só funciona uma vez.
  5. Crie a nova senha e entre com ela.
Contas inativas ou que ainda usam senha provisória não recebem o e-mail, embora a tela mostre a mesma mensagem. O limite é de 5 pedidos a cada 15 minutos.

Problemas comuns

Procure a mensagem que apareceu no terminal ou na tela.

O que apareceO que fazer
"a execução de scripts foi desabilitada neste sistema"Use npm.cmd e npx.cmd no lugar de npm e npx.
Erro de conexão com o Docker (docker daemon, pipe)Abra o Docker Desktop e espere iniciar.
defina POSTGRES_PASSWORD no .envFalta o backend\.env. Volte ao passo 2.
port is already allocatedOutro programa usa a porta 5434, 1025 ou 8025. Feche-o ou troque a porta no .env.
P1001: Can't reach database serverO banco não está no ar. Rode docker compose up -d e espere ficar healthy.
P1000: Authentication failedA senha do .env não é a do banco já criado. Use o .env antigo. Se puder perder os dados, rode docker compose down -v e refaça os passos 3 e 4.
JWT_SECRET does not existPreencha JWT_SECRET no backend\.env.
Cannot find module '…/generated/prisma/…'O Prisma Client não foi gerado. Em backend, rode npx.cmd prisma generate e repita o comando.
EADDRINUSE na porta 3333A API já está aberta em outro terminal. Feche a outra.
Site: "Não foi possível conectar ao servidor"Veja se a API está rodando e se o site está em http://localhost:5173, igual ao FRONTEND_URL.
O link do e-mail não abreDeixe só FRONTEND_URL=http://localhost:5173 no backend\.env, reinicie a API e peça outro link.
O link do e-mail volta para a página inicialO site em execução está sem a página de redefinir senha. Confira se ele foi iniciado na pasta atualizada do projeto.
