Documentação do Hemobridge

Plataforma web para conectar doadores de sangue às necessidades reais de estoque dos bancos de sangue, com tipo sanguíneo validado por um profissional de saúde antes de qualquer direcionamento.

React NestJS PostgreSQL TCC — ADS UTP
01 — VISÃO GERAL

Introdução

Muita gente disposta a doar sangue simplesmente não sabe onde fazer isso, ou se o seu tipo sanguíneo é o que está em falta em algum banco de sangue naquele momento. As informações costumam estar espalhadas entre redes sociais, campanhas pontuais e balcões de hospital, sem um canal único e atualizado.

O Hemobridge nasce para resolver esse desencontro: uma plataforma que centraliza as necessidades de estoque de cada banco de sangue por tipo sanguíneo e direciona o doador certo para o lugar certo, no momento certo. Como o tipo sanguíneo é um dado crítico para a segurança de uma transfusão, o sistema não aceita autodeclaração — cada cadastro passa pela validação de um profissional de saúde a partir de exame laboratorial.

02 — VISÃO GERAL

Objetivos

O objetivo geral do projeto é desenvolver uma plataforma que centralize as necessidades de estoque dos bancos de sangue por tipo sanguíneo, direcionando o doador ao local onde sua doação é mais necessária, sempre com o tipo sanguíneo validado por um profissional de saúde.

Objetivos específicos

Pré-cadastro do doador

Coleta de dados básicos e consentimento LGPD antes da validação médica.

Agendamento com um médico

O paciente marca uma consulta online para iniciar o processo de validação do seu tipo sanguíneo.

Solicitação e envio de exames

O médico solicita exames e o paciente anexa os resultados para análise.

Registro do tipo sanguíneo

O médico confirma o tipo sanguíneo com base no exame e aprova a ativação da conta.

Centralização das necessidades

Cada banco de sangue mantém suas necessidades de estoque por tipo sanguíneo atualizadas em um único canal.

Consulta e notificação

O doador consulta por localização e tipo sanguíneo, e é notificado quando surge uma necessidade compatível.

03 — TÉCNICO

Arquitetura e tecnologias

O Hemobridge segue uma arquitetura com front-end e back-end separados, escolhida para lidar com múltiplos domínios de negócio — pacientes, médicos, bancos de sangue e notificações — sem comprometer a manutenibilidade do sistema.

React

Biblioteca de interface baseada em componentes, escolhida por reaproveitar elementos como cartões de bancos de sangue e filtros de busca entre diferentes telas.

NestJS

Framework Node.js em TypeScript, organizado em módulos com injeção de dependência — adequado para separar autenticação, gestão de estoque e agendamento em domínios independentes.

PostgreSQL

Banco relacional com conformidade ACID, escolhido pela consistência em atualizações concorrentes de estoque feitas por diferentes hospitais ao mesmo tempo.

05 — TÉCNICO

Visão geral da API

A API é organizada em módulos NestJS que espelham os domínios levantados nos requisitos funcionais. Abaixo, os principais grupos de rotas previstos para a versão inicial do backend.

// Autenticação e perfis (RF11, RF14)
POST /auth/login
POST /auth/registro

// Pacientes e validação médica (RF01–RF13)
POST /pacientes            // pré-cadastro
POST /consultas            // agendamento com médico
POST /exames               // envio de resultado de exame
PATCH /pacientes/:id/aprovacao

// Bancos de sangue e estoque (RF15–RF22)
GET /bancos-sangue?tipo="O-"&lat=..&lng=..
PATCH /bancos-sangue/:id/necessidades

// Notificações (RF25)
GET /notificacoes/doador/:id

Este é um panorama de arquitetura baseado no levantamento de requisitos do projeto — os endpoints finais podem variar durante a implementação.

06 — USO

Como funciona

Para quem quer doar

Pré-cadastro

Informe dados básicos (idade, peso) e aceite o tratamento de dados sensíveis conforme a LGPD.

Consulta com um médico

Escolha um horário disponível para uma consulta online de validação.

Envio do exame

Anexe o resultado do exame solicitado pelo médico durante ou após a consulta.

Aprovação da conta

Com o tipo sanguíneo confirmado, o médico aprova o cadastro e ativa a conta de doador.

Busca por necessidade

Filtre bancos de sangue por localização e tipo sanguíneo compatível com o seu.

Notificação

Receba um aviso automático quando surgir uma necessidade compatível com seu tipo.

Para bancos de sangue (hospitais)

Um representante do hospital cadastra e atualiza as necessidades de estoque por tipo sanguíneo, registra a data de coleta de cada lote e acompanha indicadores de doação — sempre restritos aos dados do próprio hospital.

09 — MAIS

Perguntas frequentes

Por que o tipo sanguíneo não pode ser informado pelo próprio doador?

Porque a compatibilidade sanguínea é decisiva para a segurança de uma transfusão. Um erro de autodeclaração poderia comprometer toda a lógica de direcionamento do sistema — por isso o registro exige exame validado por um profissional de saúde.

Um hospital consegue ver os dados de outro hospital?

Não. Os dados de estoque, pacientes e exames são logicamente isolados por hospital. Apenas o administrador tem acesso a dados agregados de todas as instituições cadastradas.

O Hemobridge substitui o cadastro em bancos de sangue oficiais?

Não. A plataforma direciona o doador ao local certo, mas o processo de doação em si continua acontecendo presencialmente no banco de sangue ou hospital parceiro.

Como funciona a notificação de necessidade compatível?

Quando um banco de sangue atualiza sua necessidade de estoque, o sistema verifica quais doadores aprovados têm tipo sanguíneo compatível com aquela necessidade e envia uma notificação a eles.

É possível excluir meus dados da plataforma?

Sim. O paciente pode solicitar a exclusão de seus dados pessoais a qualquer momento, respeitadas eventuais obrigações legais de retenção previstas na LGPD (Art. 16).
